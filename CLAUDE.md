# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Ewamon Remastered: an HD-2D creature-collector MMO. Three.js WebGPU client, Colyseus + PostgreSQL (PGlite in dev)
server, pnpm workspace (`packages/*`, `tools/*`), Node >= 22.

Start with `HANDOFF.md` (state, open items, dev accounts, dev tips), then `.design/SPEC.md` (binding contract,
assembled from `.design/spec/*.md`). The old game `C:\Users\Flowmatic - Redouane\Ewamon` is a read-only reference.

## Commands

- `pnpm check`: typecheck + lint + lint-rule tests + all tests + build (what CI runs, on Node 22 and 24). Green before
  every commit to `main`.
- `npx vitest run packages/<pkg>` for one package, `npx vitest run <path/to/file.test.ts>` for one file. Vitest aliases
  every `@ewa/*` import to its `src/index.ts`, so tests need no build. Timing tests (`perf/tick`, `aoi-fanout`, some UI
  tests) can fail under a loaded machine and pass alone; re-run them alone before calling them broken.
- `pnpm test:progression`: the headless story walk (Acts I to III + all 12 league fights, ~41 min, real time). Excluded
  from `pnpm test`; run it in the background.
- `pnpm --filter @ewa/content run validate`: the content gate (every species obtainable, heightfields, interiors,
  reachability). `pnpm --filter @ewa/content zone-map <dir> <zone>` draws a top-down debug map (unreachable = magenta).
- `pnpm dev` runs client (:5173, proxies `/api`) + server (REST :4000, WS :2567). The server needs `JWT_SECRET`
  (>= 32 chars); without `DATABASE_URL` it uses PGlite under `packages/server/.data`. The user's playtest pair may be
  running there: use the isolated pair `node scripts/dev-alt.mjs server|client` (4100 / 2667 / 5174, `.data-alt`).
- `pnpm --filter @ewa/render sandbox` (:5180, `?zone=<id>`, `&interior=<id>&at=arena`, `?demo=battle|arena`).
- Dev data: `pnpm --filter @ewa/server seed:progression | grant:creature | grant:item` (usage in HANDOFF.md). PGlite
  allows one writer: stop the dev server first, or the WAL corrupts.
- `pnpm db:generate` / `pnpm db:migrate`: Drizzle migrations in `packages/persist/drizzle`.

## Architecture

Dependency direction: `core` <- `content` <- `protocol` <- `persist` / `server`; `render` (three only) and `client`
(core, content, protocol, render) sit apart from the server side.

- **Server is the truth, the client previews with the same code.** A battle lives in the server's `BattleSession`
  (`packages/server/src/rooms/battleSession.ts`) as a core `BattleState`; every number comes from core `resolveTurn`.
  Each resolved turn is written in one transaction *before* `battleEvents` goes out, carrying
  `stateDigest = digestBattleState(state)`. The client runs the same core turn as a preview, compares digests
  (`packages/protocol/src/digest.ts`) and drops the preview + requests `battleResync` on a mismatch. This is why core
  must be deterministic and why the fuzz digests are a hard gate.
- **Movement** is predicted, not re-simulated: `packages/protocol/src/movement.ts` holds the one `MOVEMENT` table and
  `stepMovement` the client predicts with; the server validates each input against a speed cap, the dt budget and the
  zone heightfield.
- **Zones are seeded.** `ZoneDef.layoutSeed` -> content `plan.ts` (roads, buildings, props, lights) -> hand-authored
  `sculpt.ts` + `data/sculpts.ts` (cliffs, rivers, tall grass) -> heightfield. Server validation and client prediction
  both read that heightfield; the built ones in `packages/content/dist/heightfields/` are committed on purpose (the only
  tracked `dist`). Interiors are walled halls in the zone's outer band, reached by door warps.
- **Generated content.** `packages/content/src/data/{species,moves,abilities,items,orbs,consumables,typechart}.ts` are
  generated by `pnpm --filter @ewa/content run migrate` from `.design/legacy/` (verbatim, never edit) plus
  `.design/additions/{species,moves,patches}.js`. Change the additions or the generator, not the output.
- **Server** (`packages/server/src`): Colyseus `rooms/` (`ZoneRoom` at 20 Hz, `ArenaRoom` for out-of-world PvP) host
  session modules (`battleSession`, `tradeSession`, `raidSession`, `towerSession`) that import no Colyseus and test
  alone; `rest/` is Fastify + JWT; `game/` holds the world systems. Env switches (`WILD_ENCOUNTERS`, `TRAINER_SIGHT`,
  `RIVAL`, `NPC_TOOLS`) have different defaults under `testEnv`.
- **Client** (`packages/client/src`): React shell + zustand state around the render package's 3D world. CSS modules
  only. LLM calls (local gemma under llama.cpp, `/npc/llm/v1`) stay in the client (`talk/llm.ts`), always with a
  template fallback; any effect on the save goes through a capped server route, so server tests never need a model.
- **tools/**: asset pipelines (`pnpm sprites | models | materials`, audio, `audit:assets`). Art sources under
  `assets-src/` are gitignored. The creature atlas has a byte ceiling; ask before raising it.

## Laws (lint-enforced: `eslint.config.js`, `eslint/local-rules.js`)

- `@ewa/core` imports nothing and iterates deterministically; client preview and server truth run the same bytes.
- `@ewa/content` depends on `@ewa/core` and zod only. `@ewa/render` imports only `three`. The server never renders.
  The client never imports server or persist. No inline styles in the client (`ewa/no-inline-style`).
- `packages/core/test/fuzz-digests.json` (1,000-battle singles fuzz) must stay byte-identical: new battle inputs are
  optional with defaults. Doubles have their own digests file.

## Rules of the build

- Work in the main checkout on `main`; no worktrees or feature branches. Other sessions may have uncommitted files:
  stage your own paths explicitly, never `git add -A`.
- Any change to `.design/spec/*.md` needs a `.design/spec/CHANGELOG.md` entry in the same commit, then
  `node .design/spec/assemble.mjs` (the `scripts/check-spec-changelog.mjs` gate, also in CI).
- Each package records spec deviations in its `IMPLEMENTATION-NOTES.md`.
- Content additions never become story gates and must keep the progression fixtures valid. `ZoneDef` npcs, trainers,
  items, lore, warps and spawn feed the layout RNG and the heightfield: moving one reshuffles that zone (plan fixture
  `packages/content/test/fixtures/r1-pre-move.json`, walker fixtures). Interiors, obstacles and arrival points are
  separate layers for that reason.
- A signature move needs a cinematic entry and a portrait (`pnpm --filter @ewa/sprite-pipeline portraits`);
  `signatures.test` fails without them.
- Live checks: the in-app Browser pane stops the game loop while hidden; use headless Chrome over CDP
  (`scripts/cdp.mjs`, launch flags in HANDOFF.md) and the isolated dev pair (`.claude/launch.json` `ewa-*-alt`). The
  alt client has no HMR: restart it after package edits. `window.__ewaWorld.walkTo(x, z)` / `.debug()` drive and
  inspect the real client.
- Downloading files from the internet (e.g. CC0 audio packs) needs the user's explicit approval in chat.
